1. What is a Shell?

  • A shell is a program that lets you interact with a computer by entering commands and receiving their output.
  • It provides a textual interface to the computer.
  • The shell interprets commands and controls how programs are executed.
  • The shell runs inside a terminal. The terminal provides the interface/window, while the shell performs command-line processing.
Remember: Terminal ≠ Shell. The terminal provides the environment for text input/output; the shell interprets and executes commands.

2. Why Learn the Shell?

  • Speed: many operations can be performed with fewer keystrokes than GUI interaction.
  • Automation: Bash can be used as a programming language to automate tasks.
  • Composition: output from one program can be passed to another using pipelines.
  • Open source: building, installing, and running many tools is commonly done through the shell.
  • CI: shell commands are widely used in software build and test pipelines.

4. Understanding the Prompt

A typical shell prompt communicates information about the current shell context:

john@XOS:~$
  • john → username
  • XOS → hostname
  • ~ → home directory
  • $ → ordinary/non-root user

5. Running Commands

The simplest command is the name of a program:

date

Commands can receive arguments:

echo hello world
  • echo → command/program
  • hello → first argument
  • world → second argument

6. Bash Argument Parsing

  • Input is normally split at whitespace boundaries.
  • Each whitespace-separated word becomes an argument.
  • The first word identifies the command/program to execute.
echo hello world

Conceptually:

command = echo
arg1    = hello
arg2    = world
Important: Multiple spaces normally act as separators. They do not necessarily remain part of an argument.

7. Quoting and Escaping

Use quotes when whitespace or special characters need to remain part of one argument. 

echo "hello     world"

The spaces inside the quotes are preserved as part of one argument.

A backslash (\) is an escape character. It prevents the shell from treating the following character as special. 

echo hello\ world

The escaped space becomes a literal space inside the argument.

Common quoting problems

  • Unterminated quotes can cause Bash to display a continuation prompt and wait for more input.
  • Paths containing spaces require appropriate quoting or escaping.
  • Correct argument parsing becomes increasingly important as command lines become more complex.

8. man — Manual Pages

man displays detailed documentation for a command. 

man echo
man date
man bash
man find
man test

Manual pages can contain descriptions, options, usage information, examples, exit statuses, and other technical details.

9. --help / -h

Many commands provide a shorter usage/help summary: 

date --help

Some commands also support:

command -h
Revision shortcut: Use man command for detailed documentation; try command --help for a shorter overview.

10. cd — Change Directory

cd changes the shell's current working directory. 

cd /bin

The shell prompt may change to reflect the new location.

11. Absolute vs Relative Paths

Absolute Path

An absolute path starts from the filesystem root. 

/home/john/dev/project

Relative Path

A relative path does not start with /. It is resolved relative to the current working directory. 

cd bin
Path Meaning
/bin Absolute path to bin under the filesystem root.
bin Relative path: look for bin inside the current directory.

12. Special Path Components

  • . → current directory
  • .. → parent directory, one level up
  • ~ → home directory
cd .
cd ..
cd ../6858

For example, if you are inside one project directory and want to move to a sibling directory: 

cd ../6858

13. Path Navigation — Mental Model

  • / = filesystem root
  • ~ = home directory
  • . = current directory
  • .. = parent directory
  • Absolute path = starts from root
  • Relative path = starts from the current working directory

14. PATH — How Commands Are Found

PATH is an environment variable containing directories where executable programs may be found. 

echo $PATH

Example:

/usr/local/bin:/usr/bin:/bin

When you type: 

date

the shell searches directories in PATH, in order, and runs the first matching executable.

The shell searches directories listed in PATH. It does not normally search the parent directories of the current directory.

which

which shows where a command is found in PATH. 

which date
/usr/bin/date

If multiple matches exist, -a can show all matches: 

which -a sh

15. ls — List Directory Contents

ls lists directory contents. Without an argument, it lists the current working directory. 

ls
ls /bin
cd → change where you are
ls → see what is there

16. Globs vs Regular Expressions

Globs and regular expressions are both pattern languages, but they are used differently.

Feature Glob Regular Expression
Purpose Simple pattern matching, commonly for paths/files General text pattern matching
Typical syntax *, ?, {} More expressive pattern operators such as character classes and repetitions
Who interprets it? Often the shell Usually the program such as grep or sed
Typical use Matching filenames/paths Matching text inside input

Globs are commonly expanded by the shell

Consider a command using a path pattern: 

ls *.txt

The shell expands *.txt before ls runs. If the directory contains a.txt and b.txt, the command effectively receives: 

ls a.txt b.txt

The glob itself is therefore not necessarily understood by ls; the shell performs the expansion.

Important distinction: A program can also implement glob matching itself. In that case, the shell may not expand the pattern first.

Globs and directory separators

In path globs, / has structural meaning. For example: 

*/file.txt

The * matches a directory component, while file.txt is matched inside that directory.

Regular expressions

Programs such as grep and sed commonly accept regular expressions as arguments. Regular expressions operate on text; they do not inherently understand concepts such as directories and files.

Remember: Glob = simpler pattern language, commonly used for filesystem paths.
Regex = more expressive text-pattern language, commonly interpreted by programs such as grep and sed.

17. find — Finding Files

find searches a directory hierarchy for files and directories matching specified conditions.

It is recursive by default: when given a path, it searches that path and everything below it.

Basic structure

find <path> <conditions>

Example: search the Downloads directory for files whose names end in .zip: 

find ~/Downloads -type f -name "*.zip"
  • ~/Downloads → directory to search
  • -type f → match regular files
  • -name "*.zip" → match names ending in .zip
Why quote the glob? Quoting "*.zip" prevents the current shell from expanding the glob. This allows find to receive the pattern and perform its own filename matching.

Time-based filtering

find can filter files based on modification time. 

find ~/Downloads -type f -mtime +30

This searches for files whose modification time satisfies the -mtime +30 condition.

Other useful find filters

  • File type
  • Filename/path pattern
  • File size
  • Modification time
  • Directories
  • Symbolic links
  • Maximum search depth

-maxdepth

-maxdepth limits how deeply find recursively searches. 

find . -maxdepth 1 -type f

The exact placement of -maxdepth matters in find expressions; consult man find when constructing more complex commands.

18. find -exec — Run a Command for Each Match

The -exec option allows find to execute another program for every matching path. 

find ~/Downloads -type f -size +100M -exec ls -lh {} \;

Conceptually:

  1. Search ~/Downloads.
  2. Keep only regular files: -type f.
  3. Keep files larger than the specified size: -size +100M.
  4. Run ls -lh for every match.
  5. Replace {} with the matching path.

{}

Inside -exec, {} represents the path found by find.

For example, if find discovers: 

/home/john/Downloads/large.iso

the executed command is conceptually: 

ls -lh /home/john/Downloads/large.iso

\;

The \; marks the end of the argument list belonging to -exec. The backslash prevents the shell from interpreting the semicolon itself.

Danger: -exec can execute destructive commands. For example: 
find ~/Downloads -type f -size +100M -exec rm {} \;

This could delete every matching file. Verify the filters carefully before replacing a harmless command such as ls with rm.

Combining find with grep

find . -type f -name "*.md" -exec grep -l "TODO" {} \;

This finds Markdown files in the current directory hierarchy and runs grep on each one.

The -l option makes grep print the names of matching files rather than the matching lines.

Useful mental model: find selects files; -exec applies another program to those selected files.

Modern alternatives

Tools such as fd provide a more ergonomic interface for many common file-search tasks. find remains important because it is widely available and highly expressive.

19. awk — Parsing Structured Text

awk is a command-line text-processing tool with its own programming language. Whereas sed is commonly used for editing/transformation, awk is particularly useful for parsing and extracting data.

Records and fields

By default, awk treats:

  • Each line as a record.
  • Whitespace-separated values as fields.

For example: 

awk '{print $2}' data

This prints the second field of every line. $2 represents the second field.

Changing the field separator

The field separator can be changed with -F. For example, using a comma: 

awk -F, '{print $2}' data.csv

The file is now treated as comma-separated data: each line is a record and comma-separated values are fields.

Remember: awk is particularly useful for extracting columns or transforming semi-structured text.

20. Pipes — Connecting Commands

The pipe operator | is a Bash language construct. It connects the output of one program to the input of another. 

command1 | command2

Conceptually: 

command1
   │
   │ stdout
   ▼
command2
   │
   │ stdout
   ▼
terminal

Example: 

grep "TODO" notes.txt | sort

The output from grep becomes the input to sort.

Core idea: A pipeline allows multiple small programs to be composed into a larger operation.

21. Input and Output Redirection

Output redirection: >

> redirects standard output into a file. 

date > date.txt

Instead of displaying the output on the terminal, the result is written to date.txt.

Important: > overwrites the destination file.

Append: >>

>> appends output to the file instead of replacing its contents. 

date >> date.txt

Running this repeatedly adds additional lines to the file.

Input redirection: <

< redirects standard input from a file. 

cat < date.txt

The program receives its input from date.txt rather than from interactive terminal input.

Operator Purpose
| Connect stdout of one program to stdin of another.
> Write stdout to a file, replacing its contents.
>> Append stdout to a file.
< Read stdin from a file.

22. Exit Status

Programs communicate whether they succeeded using an exit status.

  • 0 → success
  • non-zero → failure or another non-success condition

For grep specifically:

  • 0 → a line was selected/matched
  • 1 → no lines were selected
  • 2 → an error occurred
Important: In shell programming, a command can therefore act as a condition. Whether it is considered true or false is determined by its exit status.

23. Bash Conditionals — if

Bash can use a command's exit status as the condition of an if statement. 

if grep "2026" date.txt
then
    echo "It's 2026"
fi

The commands inside the then branch execute only when grep exits successfully.

Syntax detail: Bash closes an if block with fi.

24. while Loops

A while loop repeatedly executes commands while its condition remains successful. 

while grep "2026" date.txt
do
    echo "It's still 2026"
    sleep 10
done

sleep 10 pauses execution for 10 seconds before the next iteration.

The loop stops when the condition command exits unsuccessfully.

25. for Loops

A Bash for loop iterates over a whitespace-separated list of words. 

for var_name in A B C
do
    echo "$var_name"
done

The variable takes the values: 

A
B
C

Generating a numeric sequence

Command substitution can be used to generate the list dynamically. 

for i in $(seq 1 10)
do
    echo "$i"
done

seq 1 10 produces the numbers from 1 through 10. Bash command substitution: 

$(seq 1 10)

replaces the expression with the command's output, after which the resulting words are used by the for loop.

Distinction: Command substitution turns command output into shell text/arguments. A pipe instead connects one program's stdout to another program's stdin.

26. test and [ ]

When a Bash conditional needs to compare values or test filesystem properties, the test command can be used.

The command also has the alternate syntax [ ... ]. They refer to the same underlying command interface. 

if [ "$hello" = "$world" ]
then
    echo "equal"
else
    echo "not equal"
fi

Testing files

The -f test checks whether the specified path is a regular file. 

if [ -f date.txt ]
then
    echo "The date file exists"
fi

test supports many other conditions, including comparisons and filesystem checks. Use: 

man test

[[ ... ]]

Bash also provides the built-in conditional syntax: 

[[ ... ]]

It has similar purposes to [ ... ] but is a Bash language construct with behavior designed to reduce some common quoting and parsing mistakes.

27. Shell Built-ins vs Programs

Not everything that looks like a command is a separate executable program. Some constructs are built directly into Bash.

Construct Type
if Bash language construct
while Bash language construct
| Bash shell operator
cd Shell built-in
test Command; also exposed through [ ... ]
Remember: if, while, and | are not standalone programs. They are part of the shell language.

28. Ctrl+C — Interrupting a Command

Ctrl+C is commonly used to interrupt the current foreground process. 

Ctrl+C

When pressed, the terminal may display ^C. This is simply the terminal's representation of the control character; ^C is not itself a shell command.

Use: Press Ctrl+C to cancel a running command or interrupt a foreground process.

29. Bash Scripts

Long command sequences can be placed into a file. That file can then be executed as a Bash script.

A Bash script uses the same shell language available interactively: commands, pipes, redirection, conditionals, loops, variables, and other Bash constructs.

When Bash executes a script, it processes the commands in the file from top to bottom.

30. Shebang — #!

An executable script can begin with a shebang, also called hashbang: 

#!/bin/sh

The shebang specifies the interpreter that should execute the script.

For example: 

#!/usr/bin/python

tells the system to use that Python interpreter for the script.

The same mechanism can be used for languages that can be directly interpreted from textual source, such as Python, Ruby, R, or Julia.

Important: A language requiring a separate compilation workflow, such as conventional Java compilation, cannot simply be executed by passing the source file directly to an interpreter in the same way.

31. File Permissions

Executing a script requires the file to have the appropriate execute permission.

Use ls -l to inspect file permissions: 

ls -l lecture.sh

Permission symbols include:

  • r → read
  • w → write
  • x → execute

chmod

chmod changes file permissions. To add execute permission: 

chmod +x lecture.sh

After adding the execute bit, the script can be executed directly if its interpreter/shebang and path are valid.

32. ./ — Executing a Program in the Current Directory

Even when a script exists in the current directory, typing only its filename does not normally execute it: 

lecture.sh

The shell interprets this as a command name and searches the directories in PATH.

To explicitly execute the file from the current directory, use: 

./lecture.sh

Here ./ means: look for this executable in the current directory.

Why is the current directory not normally in PATH? This is a safety measure. If the current directory were searched automatically, an unexpected executable named like a trusted command could be executed instead.

For example, if the current directory contained a malicious file named ls, automatically searching the current directory could cause ls to execute that file instead of the intended system program.
